¿Qué es la Testing Pyramid?

Un modelo conceptual para organizar y optimizar las pruebas de software

Es una guía gráfica que muestra cómo estructurar la suite de pruebas buscando un equilibrio óptimo entre **costo**, **velocidad**, **cobertura** y **confiabilidad**[cite: 1].

⚡
Velocidad
Pruebas ultrarrápidas que entregan retroalimentación inmediata al equipo[cite: 1].
💰
Costo
Reduce la inversión manteniendo pocas pruebas complejas y costosas[cite: 1].
🛡️
Cobertura
Verificación integral del sistema en distintas capas de profundidad[cite: 1].
🎯
Confiabilidad
Garantiza estabilidad antes de liberar cambios a producción[cite: 1].

Estructura de la Pirámide

Divide las pruebas en 3 niveles estratégicos[cite: 1]. Haz clic en cada nivel para explorar.

Nivel 3: End-to-End (E2E)
Simulan flujos completos de usuario • Lentas y costosas • Menor cantidad[cite: 1]
Nivel 2: Integración
Verifican interacción entre componentes / servicios • Cantidad moderada[cite: 1]
Nivel 1: Unitarias (Base)
Prueban unidades de código aisladas • Rápidas y económicas • La gran mayoría[cite: 1]
Nivel 1 - Base

Pruebas Unitarias

Verifican funciones, métodos o módulos individuales en total aislamiento[cite: 1].

Características clave

  • Ejecución en cuestión de milisegundos[cite: 1].
  • Aíslan dependencias externas (mocks / stubs).
  • Identifican la causa exacta del error al instante[cite: 1].
  • Representan la mayor cantidad de pruebas del proyecto[cite: 1].

Ejemplo Práctico

// Cálculo del total con impuestos function calcularTotal(monto, impuesto) { return monto + (monto * impuesto); } // Prueba unitaria test('Calcula el IVA correctamente', () => { const resultado = calcularTotal(100, 0.16); expect(resultado).toBe(116); });
Nivel 2 - Medio

Pruebas de Integración

Validan que los componentes del sistema funcionen correctamente juntos[cite: 1].

¿Qué se comprueba?

  • Comunicación Backend y Base de Datos (SQL / ORM)[cite: 1].
  • Consumo de APIs REST / GraphQL externas[cite: 1].
  • Interacción entre servicios o microservicios[cite: 1].
  • Flujos de autenticación e integración middleware.

Flujo de Comunicación

1
Frontend / cliente
Envía petición con datos de registro[cite: 1].
2
API / Backend
Procesa la lógica y valida la solicitud[cite: 1].
3
Base de Datos
Almacena el registro y retorna confirmación[cite: 1].
Nivel 3 - Cima

Pruebas End-to-End (E2E)

Simulan el comportamiento real del usuario de principio a fin[cite: 1].

Características

  • Prueban la interfaz gráfica (UI), servidor y base de datos en conjunto[cite: 1].
  • Son más lentas de ejecutar y costosas de mantener[cite: 1].
  • Brindan la máxima confianza sobre el comportamiento del sistema[cite: 1].
  • Deben limitarse a los flujos críticos del negocio.

Flujo Típico E2E

1
Iniciar sesión[cite: 1]
2
Entrar al sistema[cite: 1]
3
Crear y guardar una nota[cite: 1]
4
Comprobar resultado[cite: 1]

Ventajas de la Pirámide

Por qué adoptar este modelo transforma la calidad del software[cite: 1]

🔍 Detección Temprana
Los errores se identifican antes de llegar a producción, reduciendo el impacto en el usuario[cite: 1].
⚡ Menor Tiempo de Ejecución
La base amplia de pruebas unitarias acelera el ciclo de retroalimentación del equipo[cite: 1].
💵 Reducción de Costos
Se invierte más en pruebas baratas y rápidas, optimizando los recursos del proyecto[cite: 1].
🛠️ Mantenimiento Simplificado
Las pruebas unitarias son fáciles de actualizar cuando el código cambia[cite: 1].
