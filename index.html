¿Qué es la Testing Pyramid?

Un modelo conceptual para organizar y optimizar las pruebas de software

Es una guía gráfica que muestra cómo estructurar la suite de pruebas buscando un equilibrio óptimo entre **costo**, **velocidad**, **cobertura** y **confiabilidad**.

⚡
Velocidad
Pruebas ultrarrápidas que entregan retroalimentación inmediata al equipo.
💰
Costo
Reduce la inversión manteniendo pocas pruebas complejas y costosas.
🛡️
Cobertura
Verificación integral del sistema en distintas capas de profundidad.
🎯
Confiabilidad
Garantiza estabilidad antes de liberar cambios a producción.

Estructura de la Pirámide

Divide las pruebas en 3 niveles estratégicos. Haz clic en cada nivel para explorar.

Nivel 3: End-to-End (E2E)
Simulan flujos completos de usuario • Lentas y costosas • Menor cantidad
Nivel 2: Integración
Verifican interacción entre componentes / servicios • Cantidad moderada
Nivel 1: Unitarias (Base)
Prueban unidades de código aisladas • Rápidas y económicas • La gran mayoría
Nivel 1 - Base

Pruebas Unitarias

Verifican funciones, métodos o módulos individuales en total aislamiento.

Características clave

  • Ejecución en cuestión de milisegundos.
  • Aíslan dependencias externas (mocks / stubs).
  • Identifican la causa exacta del error al instante.
  • Representan entre el 60% y 70% de todas las pruebas.

Ejemplo Práctico

// Cálculo del total con impuestos function calcularTotal(monto, impuesto) { return monto + (monto * impuesto); } // Prueba unitaria test('Calcula el IVA correctamente', () => { const resultado = calcularTotal(100, 0.16); expect(resultado).toBe(116); });
Nivel 2 - Medio

Pruebas de Integración

Validan que los componentes del sistema funcionen correctamente juntos.

¿Qué se comprueba?

  • Comunicación Backend y Base de Datos (SQL / ORM).
  • Consumo de APIs REST / GraphQL externas.
  • Interacción entre servicios o microservicios.
  • Flujos de autenticación e integración middleware.

Flujo de Comunicación

1
Frontend / cliente
Envía petición con datos de registro.
2
API / Backend
Procesa la lógica y valida la solicitud.
3
Base de Datos
Almacena el registro y retorna confirmación.
Nivel 3 - Cima

Pruebas End-to-End (E2E)

Simulan el comportamiento real del usuario de principio a fin.

Características

  • Prueban la interfaz gráfica (UI), servidor y base de datos en conjunto.
  • Son más lentas de ejecutar y frágiles ante cambios visuales.
  • Brindan la máxima seguridad sobre el valor entregado al usuario.
  • Deben limitarse a los flujos críticos del negocio.

Flujo Típico E2E

1
Iniciar sesión con credenciales.
2
Navegar al panel o dashboard.
3
Crear un nuevo elemento / nota.
4
Guardar y verificar mensaje de éxito.

Ventajas de la Pirámide

Por qué adoptar esta estrategia impulsa la entrega de valor

🔍 Detección Temprana de Fallos
Atrapar errores en pruebas unitarias cuesta una fracción que resolver un bug reportado en producción.
⚡ Feedback Continuo y Rápido
Los desarrolladores pueden ejecutar miles de pruebas unitarias en sus máquinas locales en segundos.
💵 Optimización del Presupuesto
Al mantener pocas pruebas E2E, se reducen horas de mantenimiento e infraestructura pesada de pruebas.
🛠️ Refactorización Segura
Permite reestructurar el código interno con la garantía de que nada se ha roto si la suite pasa.

Caso Práctico: E-Commerce

Aplicación de los 3 niveles en una tienda en línea real

Unitarias
Cálculos Aislados
  • Calcular subtotal y aplicar cupón de descuento.
  • Validar patrón de formato de email/password.
  • Formatear precios a moneda local.
Integración
Servicios Conectados
  • Servicio de Login + Base de Datos de Usuarios.
  • Carrito + API de inventario de almacén.
  • Procesamiento de pago + Pasarela (Stripe/PayPal).
End-to-End
Flujo Completo
  • Usuario inicia sesión.
  • Busca producto y lo agrega al carrito.
  • Paga y recibe correo de confirmación.
